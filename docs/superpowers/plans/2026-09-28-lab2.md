# Lab 2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in order. The user requested complete implementation with Lab 2 taking precedence over conflicting Lab 1 rules.

**Goal:** Deliver a validated OpenAPI 3.0.3 contract and a locally runnable CampusHub reservation API.

**Architecture:** Keep Routes → Controllers → Services. Controllers validate HTTP input and return the contract's objects, arrays, or `{ code, message }` errors. Services own the in-memory resource catalog and reservations. Mongoose schemas describe future persistence but do not open a connection or execute queries.

**Tech Stack:** Node.js, TypeScript, Express, Mongoose, and Node's built-in test runner. Use a pinned, one-off Redocly CLI for contract validation without adding project dependencies.

**Spec:** [Lab 2 assignment](https://docs.google.com/document/d/1EKIoxOw7OtgoknDJnoBVwaV8t4PokhDYlQefW0MkJzs/edit?tab=t.0); `docs/openapi.json` becomes the implementation contract.

## Design Decisions

- Use JSON, which the assignment explicitly permits, so the contract is readable with Node's built-in JSON support.
- Domain resource types are `ROOM`, `EQUIPMENT`, and `LAB`. Accept `STUDY_ROOM` as a query-only alias for `ROOM` because the assignment's curl example uses that spelling.
- Creation accepts only `resourceId`, `userId`, `startTime`, and `endTime`. The server supplies a UUID `id` and `CONFIRMED` status.
- Accept calendar-valid ISO 8601 timestamps with seconds, `Z` or a numeric offset, and optional 1–3 fractional digits; normalize returned times to UTC milliseconds. Require `startTime < endTime`.
- Reservations use half-open intervals `[startTime, endTime)`: adjacent bookings are allowed; overlapping non-cancelled bookings for the same resource return `409 DOUBLE_BOOKING`.
- Active means `PENDING` or `CONFIRMED` with `endTime` later than the current time. A user without active reservations receives `[]`.
- A syntactically valid `userId` does not require a user database. `User` is a minimal future-persistence schema with `id` and `name`.
- In-memory check and insert run synchronously in one process; data resets on restart and is not shared across workers.

## Review Focus

1. Calendar rollover, missing timezone, invalid offsets, and reversed intervals must return `400`.
2. Partial overlaps, containment, equal instants with different offsets, and simultaneous requests must not double-book.
3. Empty, repeated, unsupported, or structured query values must not silently bypass filtering.
4. Missing fields, unexpected properties, malformed JSON, wrong content type, and oversized input must produce safe contract errors.
5. User isolation, expired reservations, and adjacent/different-resource slots must remain correct after failed requests.
